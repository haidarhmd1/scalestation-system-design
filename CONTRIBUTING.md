# Contributing to ScaleStation

Thanks for wanting to help! ScaleStation is **source-available, not open source**. Please read the [LICENSE](LICENSE) first. In short:

- You may clone it and run it locally to learn.
- You may **not** publish, copy, host, sell or reuse it, or present it as your own. That includes publishing a fork or a modified version.
- Changes happen **only through the owner**: first an approved issue, then an approved pull request.

## How to propose a change

1. **Open an issue first.** Describe what you want to change and why. Wait until the owner approves it before you start working.
   *Small fixes like typos or broken links can go straight to a pull request.*
2. **Fork the repository on GitHub**, only to prepare your pull request.
3. Create a branch, make the approved change, and run `npm run build` to check it builds.
4. **Open a pull request** against `main` and link the approved issue (for example "Closes #12").
5. The owner reviews it and decides whether to merge, ask for changes, or close it. Nothing is merged without the owner's approval.
6. When your pull request is merged or closed, **delete your fork** (or keep it private to yourself). Forks may not be published or used for anything else.

By opening a pull request you confirm the work is your own, and you agree to the contribution terms in section 4 of the [LICENSE](LICENSE).

## Good contributions

- Fixes to wrong facts, numbers or explanations, ideally with a source
- Bug fixes and accessibility improvements
- Clearer wording for beginners
- Ideas for new patterns, stations or tabs (as an issue first)
